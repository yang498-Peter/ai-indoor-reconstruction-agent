# 建模 Skills、SOP 与便携工具同步（2026-09-29）

## 问题与本次范围

本地的建筑精修、IFC/SketchUp 交付和点云错位纠正经验尚未全部进入 GitHub；一次性脚本依赖现场布局、本机盘符或其他工程，不能作为新电脑的通用入口。用户要求将可复用内容提交、推送，支持后续换电脑使用。

本次复用已有独立同步工作树，保留主开发目录的其他修改。只同步流程、数据无关的工具、依赖和合成验证，不提交客户数据、案例布局、照片、模型、源目录、服务器账号或派生证据。

## 修改内容

- canonical skill 与三个参考文件：补入墙窗退进、走廊真实楼层、缓存复用、冻结同版导出、SketchUp 能力前置和 IFC 验证边界。
- 新增 `pointcloud-model-alignment.md`：区分整体配准与对象定位；按截面辨别柜面、墙体、凸出部位；分别核验空调高度与横向位置、窗分格与开扇、家具实例与支撑。
- `presentation_alignment.py`：显式输入、源/缓存/查询/模型绑定，一次加载后处理多个表面查询，应用 GLB 节点世界变换，保留竞争峰、无支持结果和可选修正前差值。它不自动认物、建模或评定精度。
- `validate_presentation_ifc.py`：独立 IFC schema/EXPRESS 与几何回读，使用声明依赖，报告实际世界包围盒、失败对象和文件哈希；空模型不能成功。
- `smoke_presentation.py`：不依赖客户数据的两套原点/旋转输入、缓存复用、GLB 节点变换与非零世界坐标 IFC 小样。只生成合成产物到新的外部工作目录。
- `sync_skills.py --check`：入口身份、命令兼容、入口体积及相关 Markdown 本地链接验证；该命令不执行网络同步。
- `requirements-presentation.txt` 与 Python 3.12 依赖约束：补齐 trimesh、IfcOpenShell、LAZ 解码器，固定测试环境。
- README、迁移文档和中文 SOP：明确完整 checkout 用法、操作命令、公开仓库数据边界和案例生产器的迁移限制。
- 展示工具 CI：Windows/Linux 矩阵，依赖检查、技能与可移植性检查、相关单元测试和零数据冒烟。

## 本地验证

- 独立 Python 3.12 虚拟环境通过仓库依赖清单安装，无系统 site-packages 或其他工程的 PYTHONPATH 依赖；`pip check` 无冲突。
- 33 项相关测试通过，覆盖错误源/缓存拒绝、节点坐标变换、不同坐标系、无支持区域、竞争峰、修正前后差异、输入覆盖保护、IFC 空模型拒绝和实际几何回读，以及已有品牌/交付工具。
- 两套不同源坐标的合成冒烟成功，复用缓存、读取 GLB 与 IFC 真实文件；输出位于独立的带空格目录。
- 技能入口校验、链接检查、仓库可移植性检查与 UTF-8 检查通过。技能官方校验器在 Windows 使用 `python -X utf8`，避免其默认系统编码读取造成误报。
- 未改变严格 Scene V2 公共契约或放宽门禁。源数据/布局、开洞宿主、接收软件和现场尺寸仍需在真实任务中核对；本次不把合成结果描述成客户模型精度或量化提速。
