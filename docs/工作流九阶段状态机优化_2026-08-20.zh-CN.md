# 工作流九阶段状态机优化记录

日期：2026-08-20
范围：实施计划 PR-B，仅处理 Pipeline V2 状态机、typed artifact、专用 evaluator 与失效传播；未修改几何算法、Evidence 独立性或 reviewer execution identity。

## 问题现象

- Skill 和文档要求九阶段，运行时代码只有七阶段，缺少 `macro-hypothesis` 与 `presentation-review`；
- 通用 `stage --status PASS` 可由调用者直接写成功，没有阶段专用判定；
- 阶段只要求“存在一个文件”，没有 artifact 类型、payload digest、producer/config/environment/input hash 契约；
- 下游失效按列表位置传播，无法区分 authority 变化与 presentation-only 变化；
- pipeline-state 没有并发旧写保护，也没有 V1→V2 的显式迁移边界；
- CLI 错误只有自由文本，自动化无法稳定读取错误码和下一步动作。

## 修改内容

1. 新增单一机器契约，九阶段顺序、直接依赖、能力要求、artifact 类型、检查向量、evaluator 和 change invalidation DAG 均从该文件加载；
2. Pipeline state 升级到 Schema V2并绑定 contract digest；旧状态必须调用 `migrate-state`，只继承可信 intake，旧下游 PASS 不继承；
3. 新增 `evaluate-stage`，禁止通用 `stage` 写 `PASS`；每阶段验证 typed artifact envelope、canonical payload digest、producer/version/git SHA、config/environment digest、input hash、时间和 authority binding；
4. Evidence、macro、presentation、regional、global 分别验证契约声明的专属检查向量，空壳或任一 `false` 返回 `STAGE_ARTIFACT_CHECK_FAILED`；
5. evaluator receipt 绑定 pipeline contract digest、evaluator code SHA 和 artifact-set digest；代码或契约变化后旧 prerequisite 不能继续使用；
6. authority、presentation、renderer、evidence、config 分别按 DAG 失效，不再把 presentation-only 修改错误传播到 authority 上游；
7. 状态写入新增进程级独占锁、revision compare-and-swap 和原子替换，旧写者稳定返回 `STATE_REVISION_CONFLICT`；
8. CLI 错误改为 `{code, message, nextActions}`，`status` 输出下一条可执行命令。
