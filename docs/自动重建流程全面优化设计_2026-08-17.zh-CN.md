# 自动重建流程全面优化设计（2026-08-17）

## 1. 结论

本项目不应把 img2threejs 或 Argus 直接改造成新的“几何真值生成器”。更适合当前彩色点云、相机位姿、照片和 Semantic Scene V2 的路线是：

```text
只读采集发现
  → 一次性 CaptureIndex
  → 全局结构证据与候选
  → Agent 显式接受/拒绝事务
  → scene-authority.json
  → 点云几何硬门
  → scene-hypothesis.json / scene-presentation.json
  → 分区审查、全局遗漏审查、视觉审查
  → 发布
```

核心原则是“算法负责提案和量化，人/Agent 负责有证据的状态迁移，LiDAR 负责几何权威，照片负责语义与材质复核”。自动化不得把候选静默写入权威场景，也不得用渲染好看掩盖点云不支持的几何。

## 2. 上游分析与可迁移逻辑

### 2.1 img2threejs

核对仓库：<https://github.com/img2threejs/img2threejs>，分析基线 `d6673386f89673a58736f8d398dd16ece67874f5`。

值得迁移的不是“从图像直接得到 Three.js”这一表象，而是它的受控生成结构：

1. 确定性硬门先运行，VLM 或 Agent 判断只能排在后面，不能把硬门失败平均掉。
2. 生成按 pass 分层，每一层只有前置条件满足才开放，避免一次生成后无法定位误差来源。
3. 修正循环有最大次数，并识别重复缺陷、振荡和平台期；同一修正重复失败时要改变路线，而不是无限重试。
4. 工作流状态原子保存，审查材料打包成一次可对比的证据面板，减少多轮上下文漂移。

在本项目中的落地：

- `geometry_workflow.py prepare/evaluate` 分离候选准备和权威验收。
- `pointcloud_scene_metrics.py` 作为不可被视觉评分覆盖的几何硬门。
- 所有候选保留 `rawCenterline` 和 `suggestedCenterline`，接受前状态恒为 `candidate`。
- 发布门在准备阶段恒为 `BLOCKED`；点云指标通过也不自动升级全局遗漏和视觉门。

### 2.2 Argus

核对仓库：<https://github.com/realsee-developer/Argus>，分析基线 `4f1b9ddae6d24970aa8fb346838be87390684ccf`。

可迁移的核心是多视图几何一致性，而不是用单帧 AI 深度替代 LiDAR：

1. 相机与深度联合估计，而不是把二者作为无关输出。
2. 帧内注意力与全局注意力交替，参考帧和共视关系由数据决定。
3. 训练损失同时约束深度、相机点、旋转点和世界点，强调多种等价几何表达之间的往返一致性。
4. 度量尺度需要明确恢复，任何归一化深度都不能直接写入源坐标场景。

在本项目中的正确角色：

- 已实现：把“多表达一致性”落到 Scene 墙体、索引点和残差/覆盖率之间的确定性检查。
- 下一阶段：把现有扫描仪位姿规范化成共视图，做位姿跳变、照片投影和可选深度残差检查。
- 不采用：把 Argus 预测深度作为权威墙面，或在默认商业链路中使用官方 RealSee3D 权重。

许可证边界：Argus 代码为 Apache-2.0，但官方 README 明确标注 RealSee3D 预训练权重仅限非商业用途。因此当前实现没有下载、打包或调用这些权重；将来如需 AI 深度，必须使用许可明确的自有/可商用权重，并继续把输出限制为残差证据。

## 3. 当前流程的四个主要瓶颈

| 瓶颈 | 原流程风险 | 优化后的约束 |
|---|---|---|
| 重复读取点云 | 每个正射、立面、局部问题都可能全量扫描 LAS/LAZ | 原始点云只在建索引时流式读取一次；全局复用紧凑瓦片，局部只读相交瓦片 |
| Agent 逐墙猜测 | 结果慢、不可复现，容易受家具和视角干扰 | 高度带栅格、Hough、原始点 PCA、双墙面配对、主方向族先产出候选 |
| 只有视觉评分 | 漂移、错厚度和断墙可能在漂亮渲染中被掩盖 | 对实测墙计算 P50/P90、长度覆盖率、最长无支撑范围并形成硬门 |
| 候选与真值混合 | 算法结果可能无审查进入发布场景 | `candidate → accepted/rejected` 必须有显式事务；候选文件不修改 Scene V2 |

## 4. 已实现的 P0 闭环

### 4.1 CaptureIndex

文件：`scene-core/capture_index.py`

- 输入目前限一个明确的 LAS/LAZ；歧义点云继续 fail-closed。
- 原始点云流式读取一次，按源平面米制坐标切成二进制瓦片。
- 大投影坐标采用 float64 源原点加 float32 局部偏移，避免直接把 UTM/国家坐标写成 float32。
- 记录源路径、字节数、修改时间、点数、点格式、边界、可选 capture fingerprint 和 index fingerprint。
- 索引以临时目录完整生成后再原子发布；源身份变化时 `validate_source` 阻断。

### 4.2 索引证据渲染

文件：`scene-core/indexed_pointcloud_evidence.py`

- 保留现有正射、地表、色带和立面像素—源坐标绑定语义。
- 全局总览需要两次读取索引瓦片：第一次建立最低/最高表面和地面参考，第二次生成地面相对高度带；不再二次读取原 LAS/LAZ。
- 立面先算走廊包围盒，再只读取相交瓦片；输出记录 `tilesRead / pointsRead / pointsReturned`。

### 4.3 结构候选

文件：`scene-core/structural_proposals.py`

- 只读结构高度带，低矮家具不作为默认墙体输入。
- Hough 只用于生成线索；每条线必须回到索引原始点做 PCA 精修和残差统计。
- 平行双墙面在合理厚度区间内配对，输出中心线与实测厚度；单面墙保留明确警告。
- 主方向族只生成 `suggestedCenterline`，`rawCenterline` 永久保留。
- 所有输出为 `CANDIDATES_ONLY`，不得直接覆盖人工/Agent 已接受几何。

### 4.4 点云—场景验收

文件：`scene-core/pointcloud_scene_metrics.py`

- 对每面普通墙建立局部查询，不扫描全局点云。
- 残差按点到墙体两侧表面计算，而不是只到中心线。
- 开口所在长度区间从“应有墙体支持”的分箱中排除，避免门窗制造假失败。
- 默认硬门：P90 残差不大于 0.08 m，长度支持率不低于 0.70。
- 只有 `accepted-measured` 墙体失败才阻断；候选和推断构件只给出提示。
- 报告绑定精确 Scene 文件 SHA-256、Scene revision、index fingerprint 和索引清单 SHA-256。

注意：该指标证明“已建墙有点云支持”，不证明“所有真实墙都已建模”。全局遗漏审查仍是独立硬门。

### 4.5 单命令工作流

文件：`scene-core/geometry_workflow.py`

准备一个全新的派生工作区：

```powershell
python .\scene-core\geometry_workflow.py prepare `
  --las '<CAPTURE>\colorized.las' `
  --capture-manifest '<WORK>\capture-manifest.json' `
  --floor-z 0.0 `
  --ceiling-z 2.8 `
  --output '<WORK>\geometry-workspace'
```

准备结果包括：

- `capture-index/capture-index.json`
- `evidence/evidence-manifest.json`
- `structural-proposals.json`
- `candidate-topology.json`
- `geometry-workflow.json`

`candidate-topology.json` 只给出 continuity、区域 axis、中心线备选和 room/adjacency proposal；
不会把 floor envelope 变成墙，也不会升级 authority。Agent 审查候选并通过 Scene API 写入
`scene-authority.json` 后，运行：

```powershell
python .\scene-core\geometry_workflow.py evaluate `
  --scene '<WORK>\scene-authority.json' `
  --workspace '<WORK>\geometry-workspace' `
  --output '<WORK>\pointcloud-scene-metrics.json'
```

没有 `accepted-measured` 墙时输出 `NOT_RUN` 并返回失败；指标不达标输出 `FAIL`；只有点云几何门满足才输出该门的 `PASS`。这三个状态都不等同于完整场景发布 GO。

## 5. 下一阶段优化顺序

### P1：准确性

1. 位姿规范化：定义 `pose-observations.json`，明确图像、内参、外参、时间戳、坐标系、单位和来源哈希；格式不明时阻断，不猜轴序或四元数顺序。
2. 共视图：依据相机视锥与点云可见区建立相邻帧/关键帧关系，检测孤立帧、位姿突跳和照片—点云错配。
3. 开口候选：在已审查墙面局部坐标中结合支持率空洞、立面边缘和照片投影提案门窗；仍只写候选。
4. 全局约束：轴族、墙厚族、共线、垂直、端点吸附、房间闭合和层高形成可解释约束图；优化结果必须与原始参数并存。
5. 遗漏损失：除“Scene → 点云”支持率外，增加“结构点云 → Scene”解释率，专门发现漏墙、漏柱和高位构件。

### P1：效率与可用性

1. 把 CaptureIndex 与 `init_reconstruction_job.py`、编排状态机正式关联，`evidence` 阶段没有索引指纹时不得完成。
2. 把局部立面、问题区域图和点云指标统一改为索引查询，淘汰每个问题一次 LAS 全扫。
3. 生成一张审查面板：原始色带、候选、点云残差、接受/拒绝状态和局部立面同屏，减少 Agent 多图切换。
4. 修正循环采用有限预算，并对重复失败、振荡和平台期输出明确路由。

### P2：可选 AI

1. SAM/语义模型只用于门窗、玻璃、家具和材质候选，不输出坐标真值。
2. 多视图深度只用于点云稀疏区的残差和置信度提示；必须先通过尺度、位姿和许可证门。
3. 任何 VLM 判断均晚于 schema、拓扑、碰撞、点云残差和证据绑定硬门。

## 6. 验收分层

| 状态 | 当前证据 |
|---|---|
| `GO_SOURCE_SYNTHETIC` | 大坐标索引、局部查询、源身份失效、双墙面配对、轴族、指标硬门、准备/验收闭环均有合成测试 |
| `NOT_RUN_REAL_CAPTURE` | 尚未对用户指定真实采集记录索引耗时、峰值内存、局部查询加速比和墙体指标 |
| `NOT_RUN_POSE_PHOTO` | 尚无通用位姿格式解析、共视图和照片投影验收 |
| `NOT_RUN_VIEWER` | 本轮未改 Viewer，也未做真实浏览器/WebView2 截图验收 |
| `NOT_RUN_ARGUS_GPU` | 未下载或运行 Argus 官方非商业权重 |
| `NO_GO_CUSTOMER_RELEASE` | 上述真实数据、全局遗漏、视觉和客户载荷门未完成 |

因此，本轮可以确认的是“核心算法与工作流接口得到可测试优化”，不能把合成测试扩张解释为真实房间、施工级模型或客户发布验收。
