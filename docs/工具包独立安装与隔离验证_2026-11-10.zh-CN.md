# 工具包独立安装与隔离验证

## 问题与修改

0.8.0 的 wheel 只有命令适配层，运行时按当前目录或源码位置查找完整 checkout，换电脑无法仅安装 wheel 使用领域实现。0.9.0 增加显式公共运行文件清单与 hatch 构建钩子，wheel 和源码包携带同一份领域代码、Schema、策略、配置、模板及工具脚本。源码包重建 wheel 使用自带资源，不依赖原始 Git 目录。

`repository.py` 优先选择包内资源并验证哈希；开发态绑定当前 Python 模块所属 checkout，忽略调用目录的其他仓库。损坏、缺少资源、冲突模块和路径逃逸明确失败。保留原 Scene API、独立 Reviewer、原子写入、质量阈值和发布门禁，没有复制一套放宽条件的领域实现。

统一命令新增 doctor 和多视图、相机控制、批处理、证据、对齐、IFC 回读及合成冒烟适配。展示依赖作为 presentation extra，完整安装约束由 uv.lock 导出。包内资源只读使用，任务仍显式选择自己的输入和输出目录；未读取、重建或迁移既有 Australia house 项目。

## 验证设计

`scripts/verify_standalone_install.py` 在 checkout 外新建虚拟环境，安装 wheel，禁止运行进程读取 checkout 源码；保留一个伪 checkout 作为当前目录并移除 PATH 中的 Git/Node，确认仍加载安装包。测试覆盖 CLI 初始化/状态/下一步、实际 MCP stdio、Reviewer 写入拒绝、无效批量接受和未完成发布拒绝、多视图拟合与留出误差、保留未观察对象的批处理、双坐标合成 GLB/IFC 回读和基准的 NOT_RUN 边界。

本地离线隔离测试明确复用现有第三方依赖路径；不执行旧 editable 项目的路径初始化。CI 的 Windows/Linux、Python 3.11/3.12 矩阵使用新虚拟环境和 Python 包源重新安装全部约束依赖，不能用本地依赖复用结果替代干净安装结论。生成的输入全是合成数据，现场原始数据没有进入测试夹具或发行包。

运行时资源损坏、缺失、当前目录被其他 checkout 干扰的拒绝测试，以及原有全量 Python、Node、MCP、合成 E2E 和构建检查继续运行。脚本与结果绑定实际 wheel 哈希；源码和安装后资源清单单独核对。现有建模交付文件的哈希在任务前后核对，独立安装验证不提供新的整屋精度或 Revit 原生编辑验收结论。

## 本地执行结果与发布条件

- Python 全量回归：416 passed、3 skipped；跳过项仍需要指定的真实 RTK 数据。
- Node Scene V2 与工作台前端合成契约：18 passed。Ruff、Mypy 的 linux/win32 目标、技能同步检查通过。
- 工作台服务合成测试：33 passed。沙箱运行先受临时目录/文件锁限制，正常 Windows 权限首次复核有一次 localhost 连接中断；保留失败日志，一次有界复跑全通过，未修改服务源码或跳过断言。
- checkout 外独立虚拟环境：实际 CLI、MCP stdio、只读 Reviewer、多视图拟合/留出、未观察对象保留、发布拒绝及双坐标 GLB/IFC 回读通过。本地第三方依赖复用条件如上，不冒充新机器干净安装。
- wheel/源码包逐项开包：128 个公共运行资源与清单哈希一致，无重复条目、原始点云、照片、GLB、IFC 或缓存。源码包能独立构建 wheel。
- Australia house 已有 13 个交付文件与此前冻结清单逐个核对，大小与 SHA-256 全部一致；没有重写建模成果或修改官网内容。

GitHub 的四组 Windows/Linux × Python 3.11/3.12 必须完成全新依赖安装和上述隔离检查，才能交付 0.9.0 发行物；以对应提交的 CI 与安装回执为准。客户工作台原有服务测试另行保留，不以打包测试代替。正式 wheel 从已提交的源码重建，运行清单记录源码提交；源码改动、实际包哈希和原有模型哈希各自记录。
