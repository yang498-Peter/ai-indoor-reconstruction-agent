# 工作流候选与全局拓扑优化记录（2026-08-21）

## 问题现象

- 旧 `structural-proposals.json` 同时放置真实墙面回波和推导中心线，单面 observation 会被默认
  0.12 m 墙厚包装成看似确定的中心线；
- Hough、face pairing 和全局 axis 使用局部排序/贪心，不能同时权衡重复墙、接头、房间闭合、
  模型复杂度和未解释强候选；
- 一个 capture 只使用一组全局轴，容易把非 Manhattan 区域或旋转翼区硬拉到错误方向；
- floor envelope、scan coverage 和 inferred room boundary 缺少独立机器语义，存在被泛化为
  full-height shell 的风险；
- clean-room 的重复玻璃分区经验没有独立 profile 边界，不应成为通用默认策略。

## 修改内容

1. `faceObservations` 保存实测 face、沿线/垂向支持区间、source tile、密度和原始残差；
   `wallHypotheses` 单独保存中心线、厚度分布、不确定性和 topology link 候选；
2. 单面墙固定生成 `observed face ± thickness/2` 两个互斥备选，任何全局偏好都保持
   `candidate / inferred-only-until-corroborated`；双面墙也必须经独立 Agent/reviewer transaction；
3. 共线 observation 先按角度、法向偏移和实际间隔做 continuity segmentation，小扫描缝保留
   `bridgedGapsM`，大缺口不合并，算法不把缺口伪装成实测墙；
4. 按空间连通区域计算独立 axis families，允许 30°/45°及其他非正交方向；
   `manhattanHardConstraint` 在 schema 和运行时都固定为 `false`；
5. bounded beam selection 同时使用点云支持、长度、残差、axis、接头、房间闭合、模型复杂度、
   重复墙和未解释候选项；T 接头通过显式端点投影/分段进入 polygonize；
6. 输出候选房间 polygon 和共享边邻接，但 artifact 固定为 `PROPOSED_NOT_AUTHORITY`；
   无合格候选或无闭合房间分别返回稳定 blocking code，并保持 `REVIEW_REQUIRED`；
7. `scanCoverageBoundary`、`floorSupportPolygon`、`inferredRoomBoundary` 只保留边界语义，
   从不自动进入 wall hypothesis；
8. 通用 office profile 为默认值；clean-room profile 带 `explicitOptInRequired=true`，只有显式
   `--topology-profile profiles\cleanroom-v1.json` 才启用；
9. 输出绑定 proposals/index/profile/config/code/source lineage hash，并使用同目录临时文件、flush、
   `fsync` 和 `os.replace` 原子发布；失败不留下正式 artifact。
