# 本地主分支统一与建模流程复核

## 问题现象

远端已合并为单一 main，但主工作树仍在旧工程化分支；两个辅助工作树保留旧分支。21 个已跟踪文件有本地改动，可复用工程化代码、案例脚本和大量成果同时处于未提交状态。远端只有一个分支不能证明本地改动已经纳入主分支，也不能代替模型归档。

## 保留和合并边界

- 已经进入 main 的多视图拟合、留出验证、独立回执及批处理工具按文件身份核对，不重复覆盖或遗漏。
- 统一 CLI、官方 MCP SDK 适配、锁定依赖、模板、平面测量、静态渲染朝向修复、候选层约束和客户工作台通用源码纳入本次审查与验证；保留主分支较新的双系统展示工作流。
- 含具体场景路径、坐标、照片、模型、IFC 或现场记录的文件保持私有，留在原位置；过时或未验证的实验入口保存原件，不作为通用工具接受。
- 两个技能参考中新增的案例链接依赖未发布的私有现场记录，因此保持 main 中已有通用版本；本地原文保存备份，没有删除案例经验。

## 实际修正

本地 CI 改为全量测试后，原开发环境没有 trimesh/IfcOpenShell，收集测试即失败。本次将展示/IFC 所需的开发依赖加入锁定项目并重验。保留公开仓库的数据边界，修正旧 README 中“私有项目”的过时描述。提供给切片工具的平面改称 provided-floor-plane，避免把未独立复核的输入直接称为已审查平面。

旧工程化测试还要求一个尚未实现、需额外授权的外部 Codex 自动审查工作流。本次没有增加外发源码或付费运行；该测试改为验证实际确定性门禁的依赖，并禁止常规 CI 使用外部 API Key 或 Codex action。外部自动审查保持 NOT_RUN；Scene V2 的独立 Reviewer、证据、阈值和发布门禁没有放宽。

## 对现有流程的判断

证据、推断和展示分层，确定性测量服务、独立 Reviewer、保留视角与哈希绑定的发布流程合理，应该继续使用。主要管理问题在于长时间积累未提交代码、工具与客户成果混放、先清理远端却未审查本地，以及验证环境与 CI 范围不同步。

今后每次交付同时闭合两份清单：代码清单记录生产器、工具、依赖和 Git SHA；私有成果清单记录输入/变换、模型、交互数据、IFC、原始观察和 Reviewer 回执。Git 主分支统一不等于这些成果通过测绘或原生 BIM 编辑验收。Australia house 已有模型和交换包应按原哈希保留，172 个未数值观察对象及 Revit 原生编辑仍保留原来的未完成边界。

打包目前是完整 checkout 的统一命令适配层，wheel 中并未包含全部 scene-core/Schema/技能资源；脱离 checkout 的独立运行不属于已实现能力。快速合成基准缺少历史性能基线和真实采集时保持 REVIEW/NOT_RUN，不能拿来证明真实住宅建模精度。

## 验证与状态

初次全量回归为 409 passed、3 skipped，三个跳过项需要各自指定的真实 RTK 采集/场景；本次没有提供这些样例，不表示 Australia house 原始数据丢失。CLI/MCP 实际内存和 stdio 测试、合成 CLI 初始化、双原点/轴向模型与 IFC 回读、工作台合成服务和前端预检均已运行。新依赖下载恢复后按原锁离线同步，没有替换版本或降低阈值。

首次云端矩阵发现 Linux Mypy 不把 os.name 的 Windows 分支视为平台条件，因而报 WinDLL 不存在；本机 Windows 检查曾通过。改为类型检查器识别的 sys.platform 分支，保留实际内存统计实现，并分别以 linux/win32 目标重验；没有忽略类型错误或让失败检查变成非阻断。

Windows runner 的备份竞态测试还暴露了路径身份问题：恢复器使用 resolve 后的备份路径，而注入器比较未解析路径，导致竞态根本没有注入。比较双方统一解析，保留“必须发生注入”和恢复后逐块哈希断言；测试未改成跳过，也没有调整备份实现来迎合测试。

私有清单包含 45,157 个文件、30,257,573,825 字节，已逐项记录 SHA-256；合并前后元数据无变化，Australia house 13 个交付文件再次核对字节哈希一致。另存 12,893 个作者文件和对应 Git 历史备份。工作台客户模型背景图保留私有原件，公开源码及运行包使用合成 SVG；构建的 wheel/源码包实际开包确认不含客户模型、点云、图片或本机缓存。

逐项结果、保存清单和最终分支身份由本次私有工作目录中的原始日志与回执记录。只有本地源码/构建、相关服务、合成冒烟和实际 GitHub CI 完成后才结束主分支统一；客户成果不随旧分支清理删除。
