# 工作流 Codex 工程化与 MCP 统一（2026-08-21）

## 问题现象

- 仓库缺少锁定的 Python 工程元数据和单一命令入口，脚本调用、依赖和测试环境容易漂移。
- Codex 标准仓库技能发现路径、root/nested `AGENTS.md` 与旧 `.codex` 兼容路径没有明确迁移边界。
- MCP 入口自行维护 JSON-RPC framing 和固定协议版本，协议职责没有交给官方 SDK。
- CI 没有覆盖 Windows/Ubuntu、Python 3.11/3.12、类型检查、构建和快速性能报告。
- 真实采集回归、性能基线和外部 Codex 审查没有运行时，必须显式保留 `NOT_RUN`，不能用合成测试代替。

## 修改文件与内容

- `pyproject.toml`、`uv.lock`：锁定 Python 3.11/3.12 依赖，提供 `indoor-recon` 命令和可复现构建。
- `src/indoor_reconstruction/`：新增统一 CLI、仓库迁移适配、官方 MCP SDK server 和快速基准报告。
- `scene-core/mcp_server.py`：只保留工具目录与领域调用，删除手写协议版本、消息循环和 framing。
- `.agents/skills/reconstruct-indoor-scene/`、root/`scene-core` 两级 `AGENTS.md`：建立标准发现路径和局部约束；旧 `.codex` 保持兼容，不覆盖并发编辑。
- `scripts/sync_skills.py`、`scripts/validate_portable_repo.py`：检查技能身份/统一入口；可移植性只审计 Git 实际发布文件，不误扫本地虚拟环境、缓存和 ignored 客户输出。
- `.github/workflows/ci.yml`：加入双系统、双 Python 版本矩阵、全量 pytest、Node、Ruff、Mypy、构建和合成基准。
- `schemas/benchmark-report-v1.schema.json`、`src/indoor_reconstruction/benchmark.py`：记录输入、代码、配置、环境与 payload 哈希，采用原子写入；关键指标阈值为 2%，运行时间和峰值 RSS 回归阈值为 15%。
- `templates/minimal-viewer/`：为新任务提供离线、无第三方 CDN 的最小展示脚手架；不把它当成真实 Viewer 验收。
- `tests/contracts/test_wp8_engineering.py`、`tests/scene-v2/test_mcp_server.py`：先建立失败契约，再通过官方 SDK 内存客户端覆盖 MCP 工具面和结构化错误。
