# 室内建模准确性与快速交付 SOP

适用：新室内点云与照片建模、已有模型纠错、允许适度推测的网页演示。目标是减少错误决策和重复计算，稳定达到空间完整、照片相符、细节合理、可交互检查的展示基准；不承诺任意数据自动达到同一精度或耗时。

严格测量验收仍由 [Scene V2 工作流](WORKFLOW.zh-CN.md) 控制。本 SOP 不写 PASS、不放宽阈值，也不把推测或漂亮渲染当作测量真值。室外/混合场景转对应场地技能。

## 1. 启动：确认数据和输出类型

1. 读取仓库指令与 `git status --short`，保护已有修改。确认是展示优化、几何测量，还是正式发布，不混淆完成口径。
2. 定位单一采集单元的实际点云、照片、位姿、标定和生成器。旧盘符、旧页面与截图仅用于查找，不替代源指纹。
3. 确认单位、Z-up、坐标系/本地参考系、原点和轴旋转。检查源基轴到显示基轴的映射，再判断方位；屏幕右侧不自动等于地理东侧。
4. 在 capture 目录之外建立独立工作目录，按源指纹和变换绑定。复用缓存，不继承旧场景坐标、房间数或验收结论。
5. 为待解决区域记录用户修正：命名以用户确认为准，宽度、高程、角度仍需量测。
6. 若需 IFC/SU，启动时探测现有运行时、目标导入器和原生 SKP 能力。先用含墙洞、跨层构件、多材质和非零变换的小样验证导出链；原生 SKP 不可用时说明 DAE + 纹理交换包的边界，继续独立工作。用户已同意暂缓的能力不反复询问。

最小区域记录：`regionId`、源/变换指纹、范围、问题、已看照片、照片能证明什么、几何依据、推测部分、下一项判别检查、修改的生产参数、验证结果。它是工作记录，不是另一套权威状态机。

## 2. 快速取证：一次准备，按问题裁切

先激活项目可用的 Python 环境，命令从仓库根目录执行。已验证环境为 Python 3.12，依赖 numpy、laspy、matplotlib、Pillow；LAZ 另需可用解码后端。不要盲目重装依赖。

```powershell
python -X utf8 scripts/indoor_presentation_evidence.py prepare --help
python -X utf8 scripts/indoor_presentation_evidence.py region --help
```

以下可复制交互执行，输入本次真实参数。数值以英文空格分隔、使用小数点；不能填写旧办公室参数来代替新数据校准。

```powershell
$cloudPath = Read-Host '本次 LAS/LAZ 绝对路径（米、Z-up）'
$workPath = Read-Host '原始采集目录之外的独立工作目录'
[double[]]$sceneOrigin = (Read-Host '已确认原点 x y z') -split '\s+'
[double]$sceneYaw = Read-Host '已确认轴旋转角（度）'
if ($sceneOrigin.Count -ne 3) { throw '原点必须为三个数' }
python -X utf8 scripts/indoor_presentation_evidence.py prepare --cloud $cloudPath --work $workPath --origin @sceneOrigin --yaw-deg $sceneYaw --length-unit metre --up-axis Z
if ($LASTEXITCODE -ne 0) { throw '准备失败，先处理绑定或输入问题' }

$regionName = Read-Host '区域标识（英文、数字、下划线或连字符）'
[double[]]$regionBounds = (Read-Host 'xmin depthmin xmax depthmax') -split '\s+'
[double[]]$regionBands = (Read-Host '三组局部高度带，共六个数：低 高 低 高 低 高') -split '\s+'
[double[]]$heightRange = (Read-Host '局部高度统计范围：低 高') -split '\s+'
$sourcePhoto = Read-Host '已经目视选中的相关照片绝对路径'
if ($regionBounds.Count -ne 4 -or $regionBands.Count -ne 6 -or $heightRange.Count -ne 2) { throw '区域或高度参数数量错误' }
python -X utf8 scripts/indoor_presentation_evidence.py region --work $workPath --name $regionName --bounds @regionBounds --bands @regionBands --height-range @heightRange --photo $sourcePhoto
if ($LASTEXITCODE -ne 0) { throw '区域取证失败，不能沿用旧图作为本次结果' }
```

多张照片重复添加 `--photo`；无照片则省略该参数，材质与遮挡补全标为推测。不得用未经查看的附近照片充当实例证据。

输出为绑定 JSON/NPZ、区域三高度带 JPG、指定照片联系表和 `*-observations.json`。缓存是 `[x, depth, height]`，Three.js 是 `[x, height, depth]`。高度带使用该坐标中的绝对高度，不会自动追踪地面；新场景需重新选带。

工具边界：当前 `region` 每次仍校验、加载整个 NPZ，不是空间索引，也不自动拟合平面/开口、建立全量照片索引或验证位姿。多区域大数据优先用现有索引服务；缓存提速不能以删除哈希检查为代价。

## 3. 先解空间语义，再做尺寸与细节

| 阶段 | 回答的问题 | 继续前留下的结果 |
| --- | --- | --- |
| 无标注总览 + 照片目录 | 房间、外围、通道和家具区在哪里？ | 空间草模与未知边界 |
| 区域照片 | 桌型、朝向、相对座椅、设备数量是什么？ | 帧 ID、可见与遮挡观察 |
| 局部点云 | 哪个面、边、高程、轴有实际支持？ | 测量范围、覆盖、残差、不确定性 |
| 生成器修正 | 开口、台阶、实例和邻接是否一致？ | 生产参数变化，不手改生成结果 |
| 展示检查 | 整体可读、局部可信、交互有效吗？ | 新截图、运行记录、剩余限制 |

先索引全部照片，再按相机/时间/区域分批联系表。等步长抽帧只适合首轮浏览，可能漏掉停留时段；某区域证据不足就回到全量序列检索。近相机不等于目标可见，两张裁图也不自动构成独立证据。

2:1 长宽比不证明等距柱状全景，先看黑边、双鱼眼布局与标定。照片与点云冲突时，先查坐标、投影、时间配对、遮挡和候选表面，不机械规定任何来源永远正确，不对矛盾墙面取平均。无法判别就保留范围或备选假设。

## 4. 将实际返工变成前置检查

- **台阶**：量相邻走道和平台清晰水平面，排除桌脚、坐垫、立板，检查倾斜与漂移。保留约估范围，家具整体随平台升高。Office 0421 的 12 cm 不是未来默认值。
- **卡座**：先确认单侧/相对长椅、桌长轴和底座；平台与座椅按每格隔板内侧净宽生成，避免统一宽度产生侧缝。
- **门洞与小空间**：结合照片、立面和低/中/高连续性，真正切开宿主墙，单独画门框、过梁、门叶。区分实景开闭状态与演示姿态；不能仅用“门都忽略碰撞”证明可通行。
- **老板桌/会议桌**：区分主工作位、访客位、会客区后再量位置、轴向和尺寸，不因房间大就默认会议桌。
- **重复工位**：逐排逐侧核对预期和实际生成数量，在网格合并前统计。取模/随机装饰不得漏掉必需电脑；总数正确不代表每排正确，新数据不默认每侧四台。
- **扫描边缘**：检查初始裁图以外的墙迹、出入口和延伸。明确有支持墙段、推测端封与未知空间，不能把裁图边界当真实边界。
- **接触细节**：低位斜视看桌脚、台阶、侧板和墙角，避免悬空、穿插、侧缝和门洞封堵；灯光阴影不能代替几何修正。
- **窗区退进**：分别量室内墙面、窗框平面、窗台与侧边退进；多高度、多相邻墙段判别，不能把窗框的强点云面当作墙面。看不到背面时，墙厚保留推测属性。修墙时联动洞口、门框、楼板和剖切，不能只移动可见网格。
- **公共走廊与多层结构**：走廊单独拟合轴向和局部地面，但保留与室内的共同坐标和连通关系。相邻入户门逐个对照，未知邻户不补内部。IFC 按实际楼层/空间组织，不能把网页 context 分组当成新楼层；检查梯井、平台和楼板边界。
- **精度统计**：保留候选面峰、墙长覆盖、剔除洞口范围和局部残差。扩大或平移 ROI 复核，避免在过薄选带内得到自证的小残差；点数、量化步长、坐标回转误差和内部阈值均不等于现场测量精度。

决策规则和局部重建依赖表见 [modeling-decisions.md](../.agents/skills/reconstruct-indoor-scene/references/modeling-decisions.md)。

### 叠加后明显错位的专项处理

先确认完整点云、缓存变换、网页抽样和当前模型身份，再区分整体坐标问题与单个物体画错。空调不能只验正面距离，还要验安装中心和高度；窗户要区分窗下墙、窗框、退进、分格和开扇；柜面不能替代真实后墙；阶梯状墙体至少比较两个高度截面。逐实例检查家具方向与支承，不能用统一摆放或总数代替定位。

使用 [点云对齐参考及批量工具](../.agents/skills/reconstruct-indoor-scene/references/pointcloud-model-alignment.md) 的 `presentation_alignment.py`，一次核验源与缓存、一次加载后处理多个区域。保存修正前后 GLB、实际节点名、ROI、竞争峰和固定视角；结果只是有条件的局部观察。窄带残差小、schema 合法、导出坐标往返小，都不能证明整个对象或房间精度。

## 5. 提速与失败恢复

源/变换改动重建缓存及依赖；照片选择改动只重做观察与受影响语义；局部几何改动重查邻接、净空与相关视角；家具家族改动检查全部同族实例；材质/UI/相机改动重跑相应浏览器检查，不重跑未变的原始测量。严格 authority 的失效范围以契约 DAG 为准。

一个区域批量修正后再生成，不为每个端点重启服务和浏览器。记录耗时与返工原因，按真实瓶颈优化。连续两轮无改善，换视角、ROI、语义家族或拓扑假设，不继续盲调小数。

将原始缓存、完整变换后的缓存、区域观测和最终交付候选分开绑定。多区域量测尽量在一次校验和加载后批量完成；所用工具支持时采用内存映射或空间索引，不能假称现有 `region` 已实现这些优化。复用命中的矫正照片和点云缓存，单独记录校验/变换、区域查询、建模、导出和网页验证耗时。导出器改动只重跑受影响格式与导入验证；UI 文案改动不重做未变测量或 IFC。

| 现象 | 下一步 | 禁止的捷径 |
| --- | --- | --- |
| `WORK_BINDING_MISMATCH` | 核对源/变换，变化则用新 work | 手改绑定 JSON |
| `STALE_CACHE` | 正确绑定下重新 prepare | 去掉指纹检查 |
| `EMPTY_REGION` / `INVALID_BOUNDS` | 查轴向、负坐标、范围顺序 | 把空切片当空房间 |
| 高度带无结构 | 查局部层级、遮挡与选带依据 | 直接补满墙并提高置信度 |
| ACL / 工具失效 | 查原因一次，用授权替代或独立可写目录 | 重复原样重试、跳过断言、删共享缓存 |
| 端口已有其他模型 | 核对服务身份，选空闲端口再验 URL | 杀不明进程、以旧页代新成果 |
| 开页返回 queued | 确认实际页面与模型身份 | 把排队等同完成 |

## 6. 真实网页检查与交付

1. 确认当前 URL、模型身份、加载完成和前台渲染。相机切换后等画面稳定；请求预设与实际 camera/target/zoom 分开记录，未获得实际值就明确说明。
2. 检查整体鸟瞰、平面、点云叠加、问题区域眼平视角和近地斜视角，并扫查其他主要区域，避免只验证做对的房间。
3. 操作旋转缩放、视角、WASD、门洞穿行、外壳/吊顶、选中与尺寸、照片加载。碰撞检查声明范围：椅子对墙不相交不是所有对象的完整证明。
4. 从生成实例读取数量，新视角完成渲染后再采样性能。查控制台、缺资源、标签遮挡、中等与较窄窗口。多语言按本任务需要检查，不强制扩展需求。
5. 保存绑定当前模型/渲染代码的截图和运行记录。几何或渲染变化使旧截图失效；本地派生照片未经相应授权不能顺手加入公开发布包。
6. 交付网页、已处理区域、未知部分、推测范围、源与结果身份、验证结果和启动方式。服务是否运行要当场核实。

### IFC / SketchUp 一次成套交付

几何冻结后再统一生成最终交换文件、预览和交付清单。后续若改几何，相关导出和截图随之失效；每个结果必须绑定本次模型哈希。沿用 [交付清单工具](../.agents/skills/reconstruct-indoor-scene/references/delivery-verification.md) 的 `snapshot / compare / verify`，不要为同一用途另写一套目录哈希工具；它本身不验证 IFC/DAE 内容或下载结果。

| 检查层 | 本次应留下的证据 | 不能替代 |
| --- | --- | --- |
| 模型几何 | 墙体内面/窗框区分、宿主洞口贯通、梯井、墙角及家具支撑检查 | 独立现场尺寸验收 |
| IFC | 单位、楼层与分类、void/fill、schema/EXPRESS、几何回读、建筑实体闭合及开洞后体积 | 指定 MVD/IDS、施工规范或 LOD 认证 |
| DAE 交换包 | 命名分组、单位/up-axis、XML 引用、有限坐标/索引、纹理与 ZIP 路径、独立加载渲染 | 原生 SKP 或 SketchUp 桌面导入 |
| 接收软件 | 绑定最终 IFC 哈希的实际导入结果；可用时检查叠加、保存和重开 | worker 成功不能替代桌面 UI 与配准验收 |
| 网页下载 | 当前服务的各格式字节哈希、真实下载行为、中英文动态面板、窄屏溢出检查 | 仅 HTTP 200 或旧版本截图 |

建筑版与源点云坐标版必须来自同一模型、共享逻辑构件身份；源坐标采用完整逆变换，包括调平和位移，不能仅交换坐标轴。两个版本是替代选择，不应一起叠加为重复模型。墙、楼板、吊顶保留生产参数以生成可编辑扫掠体；复杂家具可用分类网格。具体表示和导入器材质限制见 [BIM 导出参考](../.agents/skills/reconstruct-indoor-scene/references/bim-source-overlay.md)。

完整交付包可含模型、构件清单、坐标转换、验证摘要和简明导入说明。DAE 与纹理一起解压并保持相对目录，目标 SketchUp 版本支持导入后可另存 SKP；不改后缀冒充原生文件，不将客户数据擅自上传第三方转换。默认不打包原始照片/点云和内部机器路径。格式可用、方案展示、外部软件验收与施工准确度分别陈述。

### 展台精修与多模型主页

涉及展台弧面、屏幕漏画、品牌 Logo、门轴、自动演示或已有成果主页时，按需读取 [展台与成果集专项流程](../.agents/skills/reconstruct-indoor-scene/references/exhibition-and-collection.md)。其中包含逐实例屏幕清单、不同高度轮廓比较、台面接触与地台边线检查，以及主页 → 模型 → 返回主页的真实浏览器验证。

Logo 原图先使用技能内 `scripts/inspect_brand_asset.py` 输出透明内容边界、比例与 UV/CSS 参数；该脚本不修改图片、不推断模型放置位置。建模参数仍由现场证据决定。主页与导航单独改动无需重做未变的点云量测或完整漫游；新增检查绑定当前页面和模型，旧检查保留原输入哈希。

## 7. 换数据复用与维护

换电脑从[跨电脑迁移与零数据验证](PORTABILITY.zh-CN.md)开始。先在独立环境运行 `smoke_presentation.py` 的两套不同坐标合成输入和 IFC 回读，确认工具可运行，再接入真实数据。案例专用生产器仍须按实际空间建立，不把合成冒烟当作真实重建验收。

已有网页的建筑外观、驾驶舱、刀旗字体、多语言和部署精修，使用[展示精修与增量交付流程](展示精修与增量交付流程.zh-CN.md)。按实际变更选择检查，保留旧证据的输入绑定，不把一次案例的尺寸、物体数、速度或测试数写成下次默认值。

可复用：证据工具、参数化家具构造、材质与交互实现、区域观察字段、视觉检查方法。

必须重新建立：源/坐标绑定、房间拓扑、家具实例、地面层级、名称、照片关联、相机/裁剪范围和本次证据。`astra_office_*` 与截图清单生成器属于案例代码，仅替换输入路径不等于通用建模。

No4 的专用建模/导出脚本同样是案例实现，不是改路径即可复用的通用引擎。下次提取构造函数时先移除硬编码对象 ID、楼层高程、宿主映射和源路径，再用不同楼层/开口/坐标变换的合成小样检查行为；不要复制该案例的墙厚、支持阈值、构件数或测试结论。

技能或工具调整后，用不同原点/轴向的合成数据验证行为；新真实场景仍需网页核对。辅助工具测试不证明整个场景生成器跨数据可用。本次仅更新流程，不声明精度或速度已经提高某个百分比。

### 依据与调用链
