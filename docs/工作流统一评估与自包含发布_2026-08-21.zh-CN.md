# 工作流统一评估与自包含发布记录（2026-08-21）

## 问题现象

- 现有 `quality-report-v2` 虽然能评估 Scene V2，但 `checks` 混合布尔值、计数和分数，缺少可直接
  判定“全部硬门均通过”的 blocking check vector；
- 旧发布包只复制 `scene-authority.json`、review 和 quality 三个文件，没有携带 Scene 引用证据、
  最终 render 和 pipeline provenance；
- 发布目录只使用 `geometryDigest` 前 16 位，render、evidence、scope 或 publisher 改变时仍可能
  指向同一目录；manifest 保存绝对路径，整个包移动后无法独立验证；
- 复制过程直接写正式目录，缺少 staging 原子发布和正式目录上的发布后重验。

## 修改文件

- 统一评估：`scene-core/quality_report_v2.py`、`scene-core/quality-report-v2.schema.json`；
- 自包含发布：`scene-core/publish_bundle_v2.py`、`schemas/publish-manifest-v2.schema.json`、
  `.codex/skills/reconstruct-indoor-scene/scripts/reconstruction_loop.py`；
- 契约测试：`tests/contracts/test_v2_publish_contract.py`；
- 说明：`README.md`、`docs/SCENE-V2.zh-CN.md`、
  `docs/WORKFLOW.zh-CN.md`、`docs/自动重建流程全面优化设计_2026-08-17.zh-CN.md`。

## 修改内容

1. `quality-report-v2` 新增有序 `blockingChecks`，每项包含稳定 id、`PASS/FAIL`、失败码、实测值和
   期望；报告总状态由所有 blocking check 共同决定，85/90 分数不能覆盖其他失败；
2. 证据路径拒绝绝对路径和 `..` 逃逸；accepted evidence 的字节、双 hash 和 lineage/provenance
   继续独立复核；
3. 发布前仍以独立进程重算 quality report 并逐字段比对，旧 V1 输入继续返回
   `LEGACY_SCENE_REQUIRES_MIGRATION`；
4. bundle 自动收集 Scene 全部路径证据及 provenance receipt、resolved issue 的 review evidence，
   并生成不含本机绝对路径的 pipeline provenance index；最终 render 必须存在，可用
   `--bundle-file render=PATH` 显式绑定；
5. 包固定包含 authority、review、quality、evidence、render、provenance 六类内容；manifest 只记录
   相对路径、SHA-256、字节数和角色；
6. 完整 64 位 `bundleDigest` 绑定文件向量、publisher、job/capture、quality digests、publish scope、
   能力降级、验证算法和发布时间；任何文件或 manifest scope 修改都会破坏内容地址；
7. 发布先写同卷随机 staging 目录，逐文件 flush/`fsync`，完整验证后用 `os.replace` 原子改名，
   再对正式目录重验；已存在的相同内容地址拒绝覆盖；
8. `publish_bundle_v2.py --bundle <目录>` 可在包整体移动后独立校验；pipeline `status` 也复用同一
   verifier，篡改会把 publish stage 降为 `FAILED`。
