# 展示精修与增量交付流程

适用：已有室内/场地模型的客户展示优化、建筑补全、驾驶交互、宣传物、多语言和已授权的服务器同步。只读取本次相关分支；不把视觉通过当作测量精度或 BIM 软件验收通过。

## 从一次完整迭代中保留什么

开始时确认实际源、生成器、当前运行网址、模型/UI 哈希、待改对象和目标语言；保留可运行基线。用一份简短问题记录把用户现象、照片/点云依据、生产参数和下一项验证串起来。一次批量修正一个相关区域，生成后立即看真实网页，避免逐零件反复启动浏览器和重读点云。

| 本次现象 | 下次优先判别 | 修复后的关键检查 |
| --- | --- | --- |
| 建筑像是歪的 | 实测前立面方向，侧墙/后墙是否用了不同坐标轴 | 共用局部正交坐标系，保留真实朝向；屋脊、屋檐、封板和开口一起检查 |
| 屋顶和墙有缝 | 是缺少封板还是实测墙高错误 | 对照剖面/照片，不能为封缝随意改可见门窗高度 |
| 驾驶时镜头落到座椅后 | 驾驶舱是否误用了外部追车的世界坐标滞后 | 加速、刹车、倒车和转弯时，眼点始终位于车体局部驾驶位置 |
| 上线后地面或驾驶异常 | 打包筛选字段是否丢失地面、门轴、碰撞和复位信息 | 候选包与本地实际运行参数/行为一致，不只核对外观 |
| 刀旗字难看、笔画缺口 | 字体回退、曲线离散精度、轮廓填充规则 | 字形轮廓、孔洞、双面阅读、留白、边界及实际镜头距离 |
| 文案像内部讨论 | 页面是否直接读取 claim、证据备注或推测说明 | 客户文案独立映射；全部语言、对象卡片和动态状态逐项检查 |
| 桌面与手机正常，中间宽度遮挡 | 德文长按钮和侧栏是否压住主体 | 中等窗口单独看；语言切换保持视角、驾驶和选中状态 |

详细判别方法见 [interactive-showcase-polish.md](../.agents/skills/reconstruct-indoor-scene/references/interactive-showcase-polish.md)。产品造型、字体、宣传文字遵循本次用户输入；不自动复制 AG 案例的天线尺寸、旗帜布置或道路范围。

## 用依赖决定复测范围

源和变换变化重建其依赖；局部几何检查该区、邻接/净空和受影响视角；驾驶状态或相机改动检查运动和复位；纯文案检查所有相关页面状态和语言；字体/材质需要重新看导出模型和预览，但不重做未变的原始量测。完整漫游路径或动画变化才要求再跑完整循环；入口链接变化检查真实进入、加载和返回。

复用检查必须保留原输入哈希。模型容器变化但部分对象未变时，用生成器产生的对象几何/材质摘要证明未变；不能用物体总数相同代替。旧截图不得改哈希冒充新渲染。严格测量流程仍按契约依赖失效规则处理。

## 可复用工具和交付顺序

- 点云局部观察：`scripts/indoor_presentation_evidence.py`，一次源绑定，多次区域查询；不是精度认证或大规模空间索引。
- Logo 检查：`.agents/skills/reconstruct-indoor-scene/scripts/inspect_brand_asset.py`，读取原始透明边界、比例和 UV/CSS 参数，不重画图片。
- 发布文件核验：`.agents/skills/reconstruct-indoor-scene/scripts/delivery_inventory.py`，标准库运行；比较新增、修改、删除和非预期路径，部署前再验证完整文件集。使用方式见 [delivery-verification.md](../.agents/skills/reconstruct-indoor-scene/references/delivery-verification.md)。它不上传、不读凭据、不批准发布。

部署顺序为：当前版本/文件清单 → 隔离候选包 → 功能字段与浏览器验证 → 精确变更清单 → 再确认服务器基线未变化 → 新版本目录完整校验 → 切换版本指针 → 实际网址、下载哈希和主站健康检查。保留回滚版本。沿用用户对同一目标与范围的授权；不得夹带原始采集、凭据或其他应用改动。

## 技能维护与 GitHub 同步

将新经验写进一个最相关的参考文档，由薄入口按条件链接；不要把所有历史错误变成每次必跑的大清单。更新命令时检查当前 checkout 是否真的包含该工具；正在迁移的命令必须给出已发布工具的有效入口。

仓库有并行改动时，先检查状态，使用干净工作树整理本次路径和必要依赖。验证 UTF-8、本地文档链接、技能入口和真实工具行为；只暂存清单中的文件。推送后核对远端提交身份，不以本地提交成功代替 GitHub 同步完成。将技能规范、可复用工具和合成测试提交，采集数据、生成模型、客户照片、机器凭据与案例专属脚本留在原授权范围。

以真实瓶颈衡量后续速度：分别记录取证、生成、浏览器验证、打包和上传耗时及重复返工次数。未做可比基准时，只说明减少了哪些重复步骤，不承诺固定百分比提速。
