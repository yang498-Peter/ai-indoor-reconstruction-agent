# 工作流输入、索引与 Pose 可靠性优化记录（2026-08-20）

## 问题现象

- discovery 只按扩展名识别点云，会把仓库没有解析器的 E57/PLY/PCD/XYZ 标成可建模输入；
- capture fingerprint 使用路径、文件大小和 mtime，同大小且保留 mtime 的内容替换不会失效；
- 源单位、up-axis 与 local/CRS frame 没有硬门，英尺坐标可能被后续米制阈值误用；
- CaptureIndex tile 只检查长度，同长度篡改不会被发现，查询会把整个 tile 读入内存；
- pose 只统计文件数量，没有验证矩阵方向/刚体性、图片存在性和点云空间对齐。

- 输入适配和 pose：`scene-core/capture_readiness.py`、`.codex/skills/reconstruct-indoor-scene/scripts/discover_capture.py`、`init_reconstruction_job.py`；
- 索引与工作流：`scene-core/capture_index.py`、`scene-core/geometry_workflow.py`；
- 契约：`schemas/capture-adapters-v1.json`、`capture-manifest-v3.schema.json`、`pose-validation-v1.schema.json`；

## 修改内容

1. checked-in adapter registry 明确 LAS 可用、LAZ 需本机 backend，E57/PLY/PCD/XYZ 仅可发现但不可标记 READY；
2. V3 manifest 对重建输入流式计算内容 SHA-256，记录 source lineage、adapter digest 和显式 coordinate frame；
3. 未声明单位、Z-up 或 local/CRS reference 时返回 `BLOCKED_COORDINATE_FRAME_REQUIRED`；非米输入在索引内按记录的 `unitToMetre` 统一为源平面米制；
4. CaptureIndex V2 为每个 tile 写入内容 SHA-256 和 lineage，首次查询前校验并使用 `numpy.memmap`；旧 V1 明确要求重建；
5. transforms pose 验证刚体 camera-to-world/OpenGL 矩阵、去畸变相机内参和精确图片绑定，再用索引边界与附近真实点完成点云对齐；
6. overview、structural proposals、pose report 和 geometry workflow 均绑定 source content hash 与 CaptureIndex fingerprint；
7. manifest 与 pose 报告采用原子写入，原始 capture 全程只读。

## 验证方式

- 红测先复现不支持格式误放行、坐标 frame 缺失、内容替换不失效、pose 未验证、tile 同长度篡改、非米输入误用和非 mmap 查询；
- `python -m pytest -q tests/contracts/test_capture_readiness.py tests/scene-v2/test_geometry_pipeline.py tests/scene-v2/test_geometry_workflow.py`；
- 定向输入/索引/pose 回归 `20 passed`；排除共享工作树内与本任务无关的未跟踪测试后，本提交测试集合为 `98 passed`；
